## Metrics and independence

The common point-prediction scorer reports CATE MSE and per-replicate root-PEHE. Mean root-PEHE and square root of mean MSE are distinct output summaries. Generic runner reports are execution diagnostics; the frozen study-specific analyses govern scientific aggregation, applicability, heavy-tail handling and multiplicity. In particular, the catalog analyzer withholds M11 mean-MCSEs, mean-t intervals and p-values. Monte Carlo intervals across sample-seed blocks are not uncertainty intervals for an individual CATE prediction or evidence of a learner's uncertainty calibration. See the [metric and information contract](PROTOCOL.md).

New generic runs resolve [inference permissions](INFERENCE.md) from generator controls and declared methods/options before fitting, and record them in the manifest and summary. Student-t(3) outcome noise blocks mean-MSE uncertainty, including mixed overall summaries. Root-PEHE is handled separately: its variance can be finite when MSE variance is infinite, so its default withholding concerns unestablished fitted-method moments. Canonical defaults assume finite variance of metric scores and paired differences for the eight unchanged generic recipes; explicit declarations cover other settings. Complete-record arithmetic checks establish policy enforcement and aggregation, not moment existence or confidence-interval coverage.

These rules apply prospectively. Published smoke JSON retains its original producer diagnostics, including unsupported generic intervals emitted by earlier source. Original tutorial outputs remain in their [source snapshot](https://github.com/snu-causality-lab/obs-rct-benchmark/tree/2fe9c483b2edfc90ee1abeafc1250aba3e1782e5/notebooks); the live custom-method tutorial handles withheld uncertainty. The frozen catalog's M11 restrictions, other study-specific analyses, scientific outputs and integrated report are unchanged. Source fingerprints prevent resuming those runs under the new package.

Truth follows declared equations rather than any estimator fit. Independent component checks include finite-support Bayes sums, rational odds examples, finite-population conditional means and hand-calculated score/aggregation examples. Sequential checks perturb purchased outcomes, enforce hidden-label access, reject duplicate/excess queries, preserve costs after policy failure and reject incomplete/tampered records. Direct agreement with an author routine and independently derived mathematical identities have different evidentiary roles.

External methods are bound to locked source revisions, file hashes and import resolution. CorNet uses a separate clean checkout; Integrative R and Causal-ICM execute only the checked native entry points. The causal forest compares every tracked upstream file to its raw Git blob, binds the complete installed `grf` package, and checks selected dependency runtime files plus loaded namespace/native-library identities and Rscript. This records observed bytes and a completed-build assertion; it does not prove compiler correspondence or authenticate the whole R runtime and transitively loaded system libraries. External code is obtained separately and retains its own terms. Source-restricted entries physically omit excluded samples from fitting; the GP controls also exclude them from shared-hyperparameter optimization.

Fresh sample seeds measure sampling replication within inspected mechanisms. Deterministic replay is not an independent empirical or estimator implementation. No actual IHDP/ACIC file or unseen-mechanism challenge is evaluated here. Extreme custom quadrature, mixture, selection or callback settings still require independent numerical checks beyond input validation.

## Reproduction

Use each result packet's frozen producer and environment rather than resuming it under newer source. Install the required optional dependencies and verified upstream checkout described in [native adapter instructions](V03_ADAPTERS.md) or the main README. Analysis uses `.[analysis]`. Current source checks are `python -m pytest` and `python scripts/check_release.py`; substantial checks and fitting belong in allocated compute jobs. [Catalog](CATALOG_STUDY.md), [GP](GP_SOURCE_PILOT.md), [matched-M2](REFERENCE_STUDY.md#run-and-reproduce) and [recruitment](../results/adaptive_reference/SCIENTIFIC_RESULT.md#reproduce-and-verify) protocols identify study-specific commands. Full raw outputs, environments and logs stay on execution servers; compact records and selected assets remain public.

GitHub CI runs source/core checks, catalog/Gamma/file-fixture examples, the 24-cell adaptive smoke/replay, default notebooks and independent published catalog-CSV arithmetic. It does not rerun the full campaigns or configured native integration checks on every push. Optional integrations need their documented numerical environment and source checkout.
